RECOVERY RULES

What KOFAD protects

Server enforced

Backup files are never trusted by filename. New downloads are encrypted before leaving the server and KOFAD checks authenticated encryption, signature, checksum, record manifest and migration schema during recovery. Legacy signed plaintext backups remain restorable for compatibility. Restore and reset require the signed-in system administrator’s current password, an exact typed phrase, an explicit acknowledgement, and re-uploaded verification of the current safety backup. Backup files include database-stored media but not external cloud files, provider-held settlements, Railway environment secrets or this ChatGPT conversation. A reset does not cancel provider-side charges or revoke external credentials; independently reconcile and manage those services.
